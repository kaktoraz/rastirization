**Русский** · [English version](README.en.md)

Учебный проект по шумоподавлению изображений. В нём реализован **адаптивный
контрастно-структурный фильтр (АКСФ)** — прозрачное развитие идеи bilateral
filter, а не заявление о новом мировом классе алгоритмов. Реализация написана
на Rust; алгоритмы, метрики и генератор шума собственные. Крейт
[`image`](https://crates.io/crates/image) используется только для чтения и
записи файлов.

## Что делает метод

Для зашумлённого полутонового изображения АКСФ выполняет следующие шаги:

1. оценивает шум `σ̂` по Иммеркеру;
2. строит карту активности в окне 5×5:

   ```text
   A(p) = sqrt(max(0, V(p) − σ̂²));
   ```

3. локально выбирает диапазонный параметр bilateral filter:

   ```text
   σr(p) = σ̂ [kmin + (kmax − kmin) exp(−(A(p)/(cσ̂))²)];
   ```

4. выполняет билинейное взвешивание в окне 11×11.

В гладкой области `A(p) ≈ 0`, поэтому сглаживание сильнее; около контура или
текстуры `A(p)` больше, и фильтр становится осторожнее. Выбранные после
калибровки **только на `σ={20,30}`** параметры:

| Параметр | Значение |
|---|---:|
| `σs` | 2.0 |
| `kmin`, `kmax`, `c` | 0.85, 3.6, 1.3 |
| радиус фильтра / активности | 5 / 2 |

Кандидаты калибровки сохранены в
[`results/tables/calibration.csv`](results/tables/calibration.csv). Уровни
`σ={5,10,15,40}` при выборе параметров не использовались.

## Результат последнего воспроизводимого прогона

Протокол полутонового эксперимента: **6 сцен × 6 уровней**
`σ={5,10,15,20,30,40}`, seed `12345`, одинаковый шумный вход для всех методов.
Цифры и графики генерируются из `results/tables/results.csv` скриптом
`analysis.py`.

| Метод | PSNR, дБ | SSIM | EPI | Время, мс |
|---|---:|---:|---:|---:|
| Гауссов | 26.19 | 0.6584 | 0.3272 | 3.5 |
| Перона—Малик (собственная реализация) | 29.25 | 0.7633 | 0.5399 | 55.0 |
| Билатеральный | 27.25 | 0.5980 | 0.4958 | 64.6 |
| Билатеральный «оракул»¹ | 30.66 | 0.7989 | 0.6018 | — |
| АКСФ без адаптации | 29.60 | 0.7680 | 0.6005 | 18.8 |
| **АКСФ** | **30.35** | **0.7978** | **0.6340** | **19.9** |

¹ «Оракул» выбирает параметры по чистому эталону. Это диагностическая верхняя
граница, а не применимый метод и не строка для сравнения времени.

На четырёх реальных сценах 512×512 среднее время публичного АКСФ составило
**19.38 мс**, что ниже цели 30 мс. Публичный сепарабельный путь защищён
регрессионным тестом: при общей автоматически оценённой `σ̂` он не должен
уступать сохранённой точной 2D-версии более чем на 0.05 dB PSNR.

### Статистическая проверка

Для bilateral и АКСФ выполнено 30 независимых парных прогонов. Одна пара —
среднее по всем 36 задачам одного seed, а не отдельный пиксель или кадр.
Средняя разница составила **+3.099 dB** в пользу АКСФ; односторонний парный
`t`-тест дал `p = 2.17e−84 < 0.05`.

### Цветной YCbCr-режим

Это не три независимых RGB-фильтра. В RGB→YCbCr режиме карта активности и
`σr(p)` строятся по яркости `Y`, а `Y`, `Cb`, `Cr` фильтруются совместно с
учётом цветности. На 3 цветных сценах × 6 уровнях шума АКСФ получил
**31.23 dB / 0.8413 SSIM / 0.2728 EPI / 125.2 мс** против bilateral
**28.65 dB / 0.6053 / 0.2479 / 121.1 мс**. Полные метрики доступны в
[`results/color/tables`](results/color/tables/).

## Быстрый старт

### Требования

- Rust stable (`cargo`, проверено в GitHub Actions);
- Python 3.10+ только для графиков и документов;
- для генерации графиков: `numpy`, `matplotlib`, `pillow`;
- для DOCX/PPTX: `python-docx`, `python-pptx`.

```bash
cargo build --release --locked
./target/release/smoothing_project
```

### Обработать один файл

```bash
# Полутоновый режим; --sigma добавляет контролируемый AWGN перед фильтрацией
./target/release/smoothing_project denoise \
  -i data/clean/baboon.png -o out.png -m acsf --sigma 20 --seed 12345

# Настоящий цветной режим YCbCr
./target/release/smoothing_project denoise \
  --rgb -i data/color/fruits.jpg -o out_color.png -m acsf --sigma 20 --seed 12345
```

Поддерживаемые методы: `box`, `gauss`, `median`, `perona`, `bilateral`,
`acsf`.

### Запустить эксперимент

```bash
# Полутоновый протокол и изображения для визуализации при sigma=20
./target/release/smoothing_project bench \
  -d data/clean -o results --noise 5,10,15,20,30,40 \
  --save-sigma 20 --seed 12345

# Независимые парные seed для статистики bilateral против ACSF
./target/release/smoothing_project stats \
  -d data/clean -o results --noise 5,10,15,20,30,40 \
  --runs 30 --seed 12345

# Цветной YCbCr-протокол
./target/release/smoothing_project bench --rgb \
  -d data/color -o results/color --noise 5,10,15,20,30,40 \
  --save-sigma 20 --seed 12345

# Таблицы, графики, DOCX, PPTX и текст выступления
python3 analysis.py
python3 visualize.py --sigma 20
python3 analysis.py --color
python3 docs/build_report.py
python3 docs/build_slides.py
```

Запуск бинарника без подкоманды выводит компактную справку. Аргументы
`-i`/`--input` и `-o`/`--output` эквивалентны.

## Как устроено ускорение

| Шаг | Изменение |
|---|---|
| Карта активности | две интегральные картинки для суммы и суммы квадратов |
| Range-вес | линейно интерполируемая таблица `exp(−x)` |
| Пространственная часть | два сепарабельных прохода с исходным guidance во втором |
| Надёжность | точный 2D-путь сохранён для unit/regression test |

Исторический фиксированный замер прошёл путь **241.9 → 70.9 → 20.47 мс**
(прямой 2D → интегральная точная 2D-версия → публичная сепарабельная версия).
Новый расширенный протокол подтверждает 19.38 мс на 512×512.

## Воспроизводимость и CI

Workflow **Reproducible experiment** на этой ветке собирает release-бинарник,
запускает полутоновый, статистический, калибровочный и цветной протоколы,
создаёт графики и сохраняет производные таблицы. Workflow **CI** проверяет
`cargo fmt --check`, release-сборку и unit tests. Поэтому DOCX/PPTX, CSV и
графики имеют один источник чисел.

## Ограничения

- Проверяется только аддитивный белый гауссов шум; это не тест на импульсный
  или реальный камерный шум.
- «Оракул» не должен восприниматься как практический baseline.
- Калибровочная сетка ограничена; её нельзя расширять на тестовые уровни без
  отдельного разделения обучающих и проверочных данных.
- Время зависит от CPU/runner; для точного сравнения используйте один запуск.
